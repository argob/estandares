## Necesidad y alcance

- [ ] Está claro qué necesidad resuelve el servicio.
- [ ] Está identificado el público principal.
- [ ] La persona sabe qué resultado obtiene.
- [ ] Se explican canales disponibles y derivaciones.

## Información

- [ ] El título y primer párrafo son claros.
- [ ] Están requisitos, pasos, costo, plazo y resultado.
- [ ] La información está ordenada según la tarea de la persona.
- [ ] No hay jerga innecesaria.
- [ ] Los enlaces son descriptivos.

## Flujo

- [ ] El inicio del trámite es visible.
- [ ] Cada paso pide información necesaria.
- [ ] Hay confirmación antes de enviar.
- [ ] Hay número, constancia o estado de seguimiento.
- [ ] Los errores indican qué corregir.

## Accesibilidad

- [ ] El servicio se puede usar con teclado.
- [ ] El foco es visible.
- [ ] Los formularios tienen labels.
- [ ] Los errores son accesibles.
- [ ] Imágenes, mapas o gráficos tienen alternativa.
- [ ] Si se incluye un mapa de la República Argentina, se utilizan los mapas base obligatorios del servicio ARGENMAP (IGN) (DA 797/2022).

## Seguridad y privacidad

- [ ] Se usa HTTPS.
- [ ] Se piden solo datos necesarios.
- [ ] Se explica finalidad de los datos.
- [ ] La autenticación es proporcional al riesgo.
- [ ] No se exponen datos personales en URLs o mensajes.

## Continuidad operativa

- [ ] El servicio tiene criticidad definida cuando corresponde.
- [ ] Hay alternativa ante indisponibilidad.
- [ ] Hay responsables y canales de escalamiento.
- [ ] Hay RTO/RPO definidos para servicios críticos.
- [ ] Hay evidencia de backups, restauración o pruebas de conmutación.

## Medición

- [ ] Hay indicadores de uso.
- [ ] Se mide abandono o errores frecuentes.
- [ ] Hay canal para consultas o reclamos.
- [ ] Hay responsable de mejora continua.
